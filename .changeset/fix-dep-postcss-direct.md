deps(apps/web): bump direct `postcss` from `^8.5.15` to `^8.5.23` to clear the remaining 10 postcss Dependabot alerts.

PR #103 (vitest + tailwindcss) lifted `postcss` to a patched version transitively in some dep chains, but the direct dependency in `apps/web/package.json` was still pinned at `^8.5.15` and pnpm continued to resolve the wider dep graph to 8.5.15 because of the direct range floor. This PR raises the direct range to `^8.5.23`, which is the lowest version that contains patches for every currently-open postcss advisory:

- GHSA-6g55-p6wh-862q (patched in 8.5.12)
- GHSA-fxqj-rqcc-2cmp (patched in 8.5.23)
- GHSA-qx2v-qp2m-jg93 (patched in 8.5.10)
- GHSA-r28c-9q8g-f849 (patched in 8.5.18)

pnpm-lock.yaml now resolves `postcss` to `8.5.29` (current `^8.5.23` latest), which clears all 4 distinct postcss GHSA IDs across the 10 alerts.

Validated locally:

- `pnpm install --no-frozen-lockfile` (postinstall passes)
- `pnpm build` (turbo: 2 successful)
- `pnpm --filter errors test` (146/146)

The stale 8.4.31 version, hoisted by `next@16.x.x` itself, is unaffected by this PR (it is below 8.5.10 and is not the version Dependabot reports).

This PR is intentionally scoped to `pnpm-lock.yaml` and `apps/web/package.json`. The `apps/web/package-lock.json` lockfile is a separate artifact committed in the first commit of the repository and is not regenerated by `pnpm install`; it is read by no CI job but may be read by developers running `npm install` locally. Regenerating it requires deleting `apps/web/node_modules` to clear pnpm hoisting residue, running `npm install --package-lock-only`, then running `pnpm install` again to restore the hoisted state. That scope is out of bounds for this PR and is documented as a follow-up in PR #105.
